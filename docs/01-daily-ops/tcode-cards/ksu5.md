# KSU5 — 实际分摊执行（逐字段详解）

## 界面与入口

`KSU5` 按分摊循环把共用成本中心的初级成本以实际分摊转给接收方，生成分摊凭证。循环在 `KSU1`/`KSU2` 维护，`KSV5` 是测试入口，`KSB1` 验结果。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 成本控制范围 | 定循环所在 CO 组织 | 范围错选不到循环，误判循环丢了 |
| 循环 | 定执行哪套分摊规则（可含多段） | 循环选错 → 错误规则跑出错凭证，还要冲销 |
| 循环组（可选） | 只跑循环中某段/某组段 | 该全跑的只跑一段 → 发送方只清一半 |
| 起始 / 结束期间 | 定分摊覆盖的期间 | 跨期口径错 → 前期费用被错期分摊，重算麻烦 |
| 版本 | 默认 0（实际值） | 选错版本把分摊跑进计划版本，实际口径纹丝不动 |
| 测试运行标志 | 只出清单不生成凭证——先测后跑 | 不测试直接正式，接收方规则错全变已过账错误 |
| 明细清单 | 输出发送方到接收方的逐段明细 | 不勾 → 跑完只有汇总，出错难定位是哪段 |
| 处理组 | 新版本机制：按组批量调度循环执行（口径以你的系统为准） | 忽略分组约定 → 后台调度漏跑或重跑 |

### 关键字段深讲

**循环与段**：`KSU5` 执行的只是 `KSU1`/`KSU2` 维护的循环——每段定义发送方（成本中心 + 成本要素范围）、发送方规则（百分比等）、接收方及其规则。执行期报错九成是段配置问题，回 `KSU2` 查段，别反复重跑 `KSU5`。

**测试运行（先测后跑惯例）**：勾测试执行看明细清单——发送方余额、各段金额、接收方分摊额、错误行（如「接收方权数为 0」「百分比合计不等于 100%」）一次看清；清单干净再正式跑。

**发送方归零判据**：正式跑完的唯一验收标准：`KSB1` 查发送方余额为 0。仍有余额按序排查：要素范围漏要素、统计关键指标当期无值、分摊后又有新过账（月结顺序）。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| 发送方跑完不清零 | `KSU2` 段的要素范围与接收方规则 | [成本中心分摊配置](/03-config-notes/co-assessment) |
| 报百分比合计不足 100 | 接收方固定百分比维护 | [成本中心分摊配置](/03-config-notes/co-assessment) |
| 报接收方权数为 0 | 统计关键指标当期是否有值 | [成本中心分摊配置](/03-config-notes/co-assessment) |
| 分摊后余额又出现 | 月结顺序：分摊是否放最后跑 | [物料分类账结算](/03-config-notes/ml-closing-s4) |

## 验证（30-120 秒可执行）

控制范围 + 循环 + 当期，勾**测试运行**：明细清单无错误行、发送方余额预计清零。正式执行后 `KSB1` 查发送方当期余额为 0、接收方出现 42 类要素行。
