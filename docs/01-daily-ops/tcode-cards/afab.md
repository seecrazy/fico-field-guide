# AFAB — 折旧过账运行（逐字段详解）

## 界面与入口

`AFAB` 把当期计划折旧过账到 FI/CO，每月一次正式运行。与 `AW01N`（核对计划值）、`AFAR`（重建折旧计划）构成月结三件套——期间内改过资产，先 `AFAR` 再 `AFAB`。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 公司代码 | 定运行范围（1000） | 多公司环境漏选，另一家折旧没跑 |
| 会计年度 | 与期间共同定位目标期间 | 年度错 → 找不到期间或跑错年份 |
| 期间 | 折旧过账目标期，须顺序执行 | 跳期被拒；给已关前期补折旧同样被拒 |
| 处理模式：计划内 | 常规月度折旧过账，99% 的场景 | — |
| 处理模式：计划外 | 补过参数变更产生的计划外折旧 | 当万能补差工具，与计划内口径混淆 |
| 处理模式：重启 | 中断会话续跑；S/4 支持直接重启 | ECC 习惯先撤销整单，S/4 无此入口属版本差异 |
| 处理模式：期间 | 期间性折旧的补跑口径（语义以你的系统为准） | 误用导致重复过账 |
| 测试运行标志 | 只算清单不生成凭证——正式前必跑 | 不测试直接正式，错误清单变成已过账错误凭证 |
| 清单/输出 | 定运行清单粒度（摘要或逐资产） | 清单不留档，事后说不清当月跑了什么 |

### 关键字段深讲

**处理模式（四选一）**：计划内＝正常月度运行；计划外＝补过参数变更等产生的计划外折旧；重启＝中断续跑（S/4 支持直接重启，ECC「先撤销再重跑」习惯要更新）；期间＝特定期间口径补跑（语义以你的系统为准）。选错模式的共同症状是清单异常或重复过账——先回模式再看清单。

**测试运行（必须先跑）**：测试清单逐资产显示将过账金额与错误（科目缺失、期间锁、缺成本对象），干净才转正式。跳过测试的代价：凭证已生成，纠错只能冲销或重启。

**期间顺序**：折旧按期间顺序推进，与 MM 期间同理不可跳期。期间内改过资产（年限、资本化日期）必须先 `AFAR` 重建再跑 `AFAB`——顺序反了测试照样报错。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| 测试运行报错清单长 | 期间内是否改过资产 → 先 `AFAR` | [AFAB 折旧过账报错](/01-daily-ops/errors/afab-depreciation-error) |
| 跑完 AW01N 与总账不平 | 错误资产清单与过账日志 | [AFAB 折旧过账报错](/01-daily-ops/errors/afab-depreciation-error) |
| 报缺技术清账科目（S/4） | 技术清账科目配置 | [S/4 新资产会计差异](/03-config-notes/asset-s4-diff) |
| 折旧到 CO 报缺成本对象 | 资产时间依赖页签的成本中心 | [成本中心缺失](/01-daily-ops/errors/cost-center-missing) |

## 验证（30-120 秒可执行）

1000 + 当年 + 当期 + 计划内，先勾**测试运行**：错误清单应为空、金额摘要合理；去掉测试正式运行。抽查 `AW01N` 任一资产当期已过账折旧，与 `FAGLL03` 累计折旧当期发生额勾稽。
