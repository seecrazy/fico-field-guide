# 销售单据被信贷冻结 — Credit check blocked

> 一句话：先查 `FD32` 占用是不是真超了，再决定提额度还是 `VKM1` 释放——释放只放行这一单，不改额度。

## 消息文本

现象：`Document blocked for credit check`（单据被信贷检查冻结）。消息随信贷组与检查点而异，消息号以你的系统为准。

## 什么时候出现

- `VA01` 下单、`VL01N` 交货、`VF01` 开票三个检查点，命中 `OVA8` 配置的冻结反应。
- 客户 100001 未清发票累计，新单顶过额度。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. 额度不足：占用+新单超限 | `FD32` 查额度与占用 | 提额（走审批） |
| 2. 额度过有效期 | `FD32` 看有效期字段 | 延长有效期 |
| 3. 未清发票占满额度 | `FD33` 看占用构成 | 催收清账释放占用 |
| 4. `OVA8` 风险类×信贷组反应过严 | `OVA8` 核对该组合 | 与业务确认后放宽 |
| 5. 付款条件恶化触发风险类上调 | 查客户风险类变更记录 | 复核风险类与额度 |

## 怎么验证

**验证 T-Code**：`VKM1`
**验证判据**：提额或释放后重跑该单据通过信贷检查，`FD32` 占用同步更新
**失败对照**：仍被拦 → 多为下一个检查点接着拦，逐点核对 `OVA8`；FSCM 环境改用 `UKM_BP` 核额度
