# F.19 — GR/IR 重分类清单（逐字段详解）

## 界面与入口

`F.19` 按「已收货未开票 / 已开票未收货」拆列 GR/IR 未清项，是期末列报重分类的取数与过账工具。与 `F.13` 的分工要说死：`F.13` 才是真实清账，`F.19` 只做列报调整——把它当清账跑，未清项一分不会少，见 [GR/IR 科目余额不为零](/01-daily-ops/errors/gr-ir-not-cleared)。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 公司代码 | 决定对哪个公司出清单 | 填错公司清单为空或串公司口径 |
| 会计年度 | 限定取数的年度 | 年度错清单为空，误以为「都已清完」 |
| 期间（至） | 限定重分类基准时点 | 期间错，拆列金额与期末余额对不上 |
| GR/IR 科目（区间） | 限定分析的清账科目，示例 191100 | 区间没覆盖目标科目，清单为空或漏项 |
| 凭证选择/附加限定 | 收窄参与清单的凭证 | 限定过窄，重分类金额低估 |
| 清单/过账选项 | 只出清单，或同时过账重分类凭证 | 误选过账，生成不该有的调整凭证，需按原路冲回 |
| 测试/正式运行 | 先看清单再动账 | 直接正式过账，方向或科目错要逐笔冲 |

### 关键字段深讲

- **两列口径**：清单按行项目把 GR/IR 未清额拆成「已收货未开票」（应列应付暂估/预计负债方向）与「已开票未收货」（应列预付方向）两栏；分类基于收货与发票的配对状态。取数前提是科目激活未清项管理——没激活清单为空。
- **只列报不清账**：`F.19` 不减少任何未清项；若启用自动过账，生成的是重分类调整分录，并按惯例在次月期初自动冲回（是否冲回、冲回时点属配置口径，以你的系统为准）。错误模式：月结跑了 `F.19` 就以为 GR/IR 已清，期末余额原样带出。
- **先清后分**：标准月结顺序是先 `F.13` 把可配对的真清掉，剩余真实差异再由 `F.19` 拆列报——顺序反了清单里全是本可自动清掉的噪音。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| 跑完 F.19 未清项没少 | `F.19` 本就不清账，回 `F.13` 真清 | [GR/IR 科目余额不为零](/01-daily-ops/errors/gr-ir-not-cleared) |
| 清单金额与余额对不上 | 期间与科目区间口径 | [GR/IR 科目余额不为零](/01-daily-ops/errors/gr-ir-not-cleared) |
| 清单为空 | 科目未清项管理是否激活 | `FS00` 科目控制数据 |
| 调整凭证次月没冲回 | 自动过账与冲回配置口径 | 以你的系统配置为准 |

## 验证

公司代码 1000、会计年度当期、科目 191100 运行：清单「已收货未开票+已开票未收货」合计应等于 `FBL3N`/`FAGLL03` 中该科目未清余额；任选一行双击能追到原始收货/发票凭证。
