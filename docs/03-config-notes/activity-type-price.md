## 一句话结论

> 作业类型把成本中心对外提供的服务（人工小时、机器小时）变成「有量、有价」的计量单位：`KP26` 维护计划价，`KB21N` 确认作业量时按计划价即时结转（借订单、贷成本中心），月末 `KSII` 用实际成本÷实际作业量算出实际价并重估差异——差异按量补给消耗方后，成本中心余额归零。

## 症状

- 月结跑完，生产成本中心余额清不掉：工资折旧都进来了、作业也确认了，账上就是差一截——多半是 `KSII` 实际价格计算与重估没跑。
- 制造费用转到订单的「转换费」月月波动大，标准成本与月末实际对不上，差异没人能解释。
- `KSII` 执行报作业量为零类错误，实际价算不出来，重估整批中断。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 当期没维护计划价（`KP26` 空价） | `KP26` 查成本中心×类型×期间 | 补 120.00 类计划价后重过账确认 |
| 月末没跑 `KSII` 或没勾重估 | 查月结清单该步是否执行 | 按[月结清单](/01-daily-ops/month-end-checklist)顺序补跑 |
| 作业量 0 但成本已归集（除零） | `KSB1` 查当期确认量 | 补确认量或按兜底口径处理（以你的系统为准） |
| 成本中心与作业类型组合未激活/价格类别错 | 查成本中心主数据与类型类别 | 修正组合与价格类别后重跑 |

## 配错会怎样

- 计划价漏维护：`KB21N` 确认报无价或按 0 结转，订单成本凭空缺一大块。
- 月末不重估：成本中心月月挂余额，订单成本口径失真，CO 报表与 FI 对不平。
- 作业类型的分配成本要素类别错：确认过不了账或结转科目挂错，月结返工。

## 怎么配置

1. 先建结转载体：次级成本要素，类别 43（内部作业分配；个别口径亦见 41，类别码以你的系统为准），示意 `943000`。
2. 建作业类型主数据（`KL01` 类操作）：作业单位 H（小时）、价格类别（决定可维护计划价还是含实际价，取值以你的系统为准）、分配成本要素 `943000`。
3. 成本中心与作业类型组合：价格按「成本中心×作业类型×期间」三维维护，组合未激活则 `KP26` 找不到对象。
4. `KP26` 维护计划价：版本 0、按期间，可拆固定价与变动价。
5. 月结链条：日常 `KB21N` 确认 → 月末 `KSII` 实际价计算+重估 → 之后才订单结算/PA 结转；标准成本与计划价的口径衔接见[标准成本](/03-config-notes/co-pc-standard-cost)。

```mermaid
flowchart LR
    A[KP26 计划价] --> B[KB21N 确认]
    B --> C[借订单贷中心]
    C --> D[KSII 实际价]
    D --> E[重估差异]
    E --> F[中心余额归零]
```

## 参数与组合全解

**作业类型主数据关键字段**：

| 字段 | 管什么 | 典型坑 |
|---|---|---|
| 作业单位 | 计量单位，量与价都按它 | 单位建错（天/小时混），价格口径全错 |
| 价格类别 | 允许维护哪些价格 | 类别不含计划价时 `KP26` 录不进 |
| 分配成本要素 | 结转载体（类别 43） | 未指定时确认无科目落账 |
| 成本中心组合 | 价格挂在中心×类型×期间 | 组合未激活，计划价无处维护 |

**价格三类**：

| 价格 | 谁维护 | 口径 | 用在哪 |
|---|---|---|---|
| 计划价 | `KP26` | 年初/月度计划（120.00/H） | 确认时的结算价、标准成本 |
| 实际价 | `KSII` 计算 | 实际成本÷实际作业量 | 月末对比与重估来源 |
| 计划价重估 | `KSII` 勾重估执行 | （实际价−计划价）×作业量 | 差异按量补给消耗方 |

**与分摊的分工**：作业分配「按服务量」——有量有价，结转额随业务量走；分摊/分配「按规则比例」——无量，按权重下摊。可计量工时的场景优先作业分配，共用费用兜底用分摊，三方式边界详见[成本中心分摊](/03-config-notes/co-assessment)。

## 边缘与高级场景

- **作业量为 0 的除零**：`KSII` 对无作业量的中心算不出实际价（报错或跳过，兜底行为以你的系统为准）。预防：月结前置检查「有成本无作业」的成本中心——新增中心忘确认是高发场景。
- **计划价年中变更**：改价只影响之后的确认，已按旧价结转的金额不追溯；全部价格差统一由月末重估找平，所以月中调价不必重跑历史确认。
- **固定价与变动价**：`KP26` 可把价格拆为固定+变动两列；重估通常只作用于变动部分，固定价按产能口径不随量重估——具体口径以你的系统为准。

## 实操走查（跟着做一遍）

公司代码/成本控制范围 1000，期间 2026-11，全程约 12 分钟。前提：作业类型 `LABOR`（人工，单位 H）已建好（`KL01` 类操作，本走查直接沿用）。

1. `KP26` 维护计划价：成本控制范围 1000、版本 0、年度 2026、期间 11 至 11、成本中心 4100、作业类型 LABOR，回车进入价格总览；变动价格列填 120.00，固定价格 0.00，计划价格合计显示 120.00 CNY/H；保存，状态栏提示已保存。
2. 组合自检：步骤 1 能进入总览即代表「4100×LABOR」组合可计价；若报作业类型未分配给成本中心，回主数据查组合（相关报错见[成本中心缺失](/01-daily-ops/errors/cost-center-missing)）。
3. `KB21N` 确认作业：凭证抬头日期 2026-11-15、作业类型 LABOR；行项目接收方类型「订单」、订单号 1000123（示意），发送方成本中心 4100，数量 8，单位 H；回车后活动价格自动带出 120.00，行金额显示 960.00；保存生成 CO 凭证。
4. `KSB1` 查发送方：成本中心 4100、期间 11 月，执行；列表出现一条 `943000` 贷方 960.00（转出），对方对象是订单 1000123。
5. 查接收方：`KOB1` 看订单 1000123 当期行项目，对应借方 960.00 已入订单成本。
6. 口径铺垫：示意当月 4100 共归集工资折旧等实际成本 5,200.00，全月确认 40 H（本例 8 H+其他 32 H）——即计划价结转 4,800.00，与实际差 400.00。
7. `KSII` 试算：成本控制范围 1000、期间 2026-11、成本中心 4100，勾「实际价格计算」、暂不勾重估、测试运行；清单给出实际价 = 5,200.00÷40 H = 130.00，与计划价 120.00 并列对比。
8. `KSII` 正式重估：同屏勾「重估实际作业分配」正式执行；每小时补结 (130.00−120.00)=10.00，本订单 8 H 补 80.00、全月共补 400.00；回 `KSB1` 再查 4100，`943000` 贷方合计 5,200.00，成本中心余额归零。

## 怎么验证

**验证 T-Code**：`KSB1`
**验证判据**：`KB21N` 确认 8 小时后，`KSB1` 查发送方成本中心出现 `943000` 贷方 960.00 = 8 H × 计划价 120.00；月末 `KSII` 重估后该中心当期余额为 0。
**失败对照**：无转出行 → `KP26` 当期无价或组合未激活（根因表第 1、4 行）；金额不等于量×价 → 查价格类别与固定/变动拆分口径（以你的系统为准）；余额仍不清 → 重估没跑或跑后又新过账。
