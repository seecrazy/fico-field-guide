# GR/IR 科目余额不为零 — 月结 F.13 清账失败

> 一句话：GR/IR 有余额先用 `MB5S` 分清「真没到票」还是「清账没配对」；`F.19` 只是期末报表重分类，替代不了 `F.13` 的真实清账。

## 消息文本

现象：月结跑 `F.13` 后，`FBL3N` 里 GR/IR 科目（示例 191100）的未清项原样挂着。非固定报错消息，常见伴随提示为「无法配对」，以你的系统为准。

## 什么时候出现

- 月中跑了 `F.13`，收货与发票有一边没到齐。
- 期末 `F.19` 重分类做完了，未清项却一分没少。
- PO 收货 100、发票只来 95，差量长期挂账。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. 收货与发票数量/金额未匹配（真实业务差异） | `MB5S` 按 PO 比对已收货 vs 已开票清单 | 催票、补收货或退货，把数量追平 |
| 2. 清账标准没配对上：科目没勾选或选择参数过窄 | `F.13` 测试运行看「已选/已清」统计 | 勾选 GR/IR 科目与采购订单号等标准后重跑 |
| 3. 数量平但金额不平（价格差异已进 PRD 科目） | `FBL3N` 看未清项是否只剩差额 | 按客户政策手工清账，差异归属需业务确认 |
| 4. 把 `F.19` 当清账工具用 | 对比 `F.19` 运行前后 `FBL3N` 未清项 | 顺序纠正：先 `F.13` 真清账，`F.19` 只做列报重分类 |

## 怎么验证

**验证 T-Code**：`F.13`
**验证判据**：测试运行可匹配项全进待清清单；正式运行后 `FBL3N` 只剩真实业务差异
**失败对照**：清完仍大额挂账 → `MB5S` 拉差异 PO 清单，回到第 1 类根因
