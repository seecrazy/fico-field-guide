# KSB1 — 成本中心实际行项目（逐字段详解）

## 界面与入口

`KSB1` 查成本中心**实际**行项目，是 CO 侧的 `FB03`：FI 过账、折旧、分摊结果都能按中心追溯。汇总类报表看合计，`KSB1` 看行明细并可下钻，也是月结分摊后「发送方归零」核查的第一入口。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 成本控制范围 | 定 CO 组织口径（1000 所在范围） | 范围错 → 中心选择列表为空，误以为中心没了 |
| 成本中心 / 中心组 | 定查询对象；组可一次查多个中心 | 单中心与组口径混用，余额汇总对不上 |
| 会计年度 + 期间 | 定取数期间（可区间跨月） | 期间口径与月结对账日不一致，各说各话 |
| 版本 | 默认 0 = 实际过账版本 | 版本选错 → 查到预算/模拟版本，金额「少一截」 |
| 实际 / 计划值 | 主口径是实际；计划数在计划版本 | 口径弄反 → 拿计划数对总账，永远差一截 |
| CO 凭证号 | 精确过滤某笔过账 | FI 凭证号不等于 CO 凭证号，用错号查空 |
| 成本要素区间 | 按要素类别收窄（40 初级 / 42 分摊次级） | 不筛 42 → 分摊行与原始费用混在一起难解读 |
| 布局（报表变式） | 定显示列与排序 | 默认布局看不到源凭证列，找不到钻取入口 |
| 行项目钻取 | 双击行进 CO 凭证再溯源 FI/分摊凭证 | 只看汇总不下钻 → 「这团钱哪来的」答不上 |

### 关键字段深讲

**成本中心与中心组**：单中心查明细，中心组查汇总口径。分摊月结的发送方/接收方常按组定义，核查归零按组跑最省事；组在 `KSH1`/`KSH2` 维护。

**版本 0**：版本 0 是实际过账落点，1 常作计划/预算版本（以你的系统为准）。金额「少一截」「多出计划数」先查版本再怀疑数据。

**42 类次级成本要素行**：分摊（`KSU5`）落账后，接收方看到的是 42 类要素汇总行——原始构成被聚合是分摊固有属性，不是丢数据；要明细改用分配（`KSV5`）或回发送方下钻。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| 行项目查不到 | 版本、期间、实际/计划口径 | [成本中心分摊配置](/03-config-notes/co-assessment) |
| 发送方分摊后仍有余额 | 42 类行与 40 类行的构成 | [成本中心分摊配置](/03-config-notes/co-assessment) |
| 折旧/费用没到中心 | 资产或科目主数据的成本中心归属 | [成本中心缺失](/01-daily-ops/errors/cost-center-missing) |
| 生产成本不在中心里 | 261 发料走订单容器，先查订单 | [生产订单结算](/03-config-notes/co-pc-order-settlement) |
| 月结后中心余额又变了 | 物料账重估是否在分摊后落账 | [物料分类账结算](/03-config-notes/ml-closing-s4) |

## 验证（30-120 秒可执行）

控制范围 + 一个管理类中心 + 当年当期 + 版本 0 运行：应看到 40 类初级费用行（含折旧）；双击任一行能钻到源 FI 凭证；若已跑分摊，42 类行金额与发送方转移额一致。
