# 过账期间未开 — Posting period 011 2026 not open（OB52）

> 一句话：先分清 FI 期间没开、变式没对上，还是 MM/FI 期间不同步——修法各不同。

## 消息文本

原文现象：`Posting period 011 2026 not open`（过账期间 2026 年第 11 期未开放）。触发消息随模块不同（FI、MM、CO 各自的消息类），消息号以你的系统为准。

## 什么时候出现

- 月初第一笔 `FB50`/`FB60`：新期间还没开。
- 年结后首月：会计年度翻了，区间还停在去年。
- 收货或发票校验报期间错：MM 期间（`MMPV`）与 FI 期间（`OB52`）不同步。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. FI 期间区间没放开（最常见） | `OB52` 查公司代码 1000 所在变式，核对年度+期间区间与账户类型（A/D/K/S） | 补开区间，注意「+」账户类型是兜底行 |
| 2. 凭证日期/过账日期跨期或年份敲错 | 回到凭证看两个日期 | 把过账日期改到已开期间 |
| 3. 期间变式与期间定义没对上 | `OB52` 首屏看变式编号，`OB29` 核对该变式的期间数 | 对齐变式后再维护区间 |
| 4. MM 与 FI 期间不同步 | `MMPV` 首屏看 MM 当前期间，对比 `OB52` 的 FI 区间 | `MMPV` 把 MM 期间开/关到与 FI 对齐 |

## 怎么验证

**验证 T-Code**：`OB52`
**验证判据**：目标期间对全部账户类型（含「+」行）都落在开放区间内
**失败对照**：仍报期间错 → 核对凭证的公司代码与过账日期是否被默认值带错；MM 单据再查 `MMPV`
