# FBL3N — 总账科目行项目清单（逐字段详解）

## 界面与入口

`FBL3N` 是 ECC 按总账科目查行项目的主力；S/4HANA 新总账环境改用 `FAGLL03`（多分类账），两者分工见 [版本差异总表](/00-about/version-matrix)。GR/IR、银行、内部往来等未清项管理科目的清账排查，`FBL3N` 是第一入口。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 总账科目 | 限定科目或区间，GR/IR 排查示例 191100 | 输错科目看的是别处余额，误判挂账规模 |
| 公司代码 | 决定读哪个公司的行项目 | 填错公司清单为空或串公司数据 |
| 未清项 | 只列未清项（科目须激活未清项管理） | 科目没开未清项管理时勾了也只出全部项，谈清账配对无从下手 |
| 已清项 | 列已清项，可限清账日期 | 日期太窄看不到早期已清记录，误以为 F.13 没跑 |
| 全部项 | 未清+已清一次列出 | 对账龄/挂账口径时混入已清项，数字虚高 |
| 日期范围（过账/凭证） | 收窄行项目区间 | 范围错漏旧账，合计与科目余额对不上 |
| 币种 | 决定金额显示口径 | 本外币口径混看时差额恰为折算额 |
| 清账日期 | 配合已清项定位何时被清 | 不填看不出「何时清的」，追 F.13 运行批次困难 |

### 关键字段深讲

- **总账科目 + 未清项口径**：只有 `FS00` 里激活「未清项管理」的科目（GR/IR、银行、统驭类往来）才有未清/已清之分；费用科目查未清项没有意义。错误模式：在普通损益科目上找「未清项」，清单为空还以为是权限问题。GR/IR 未清挂账的完整路径见 [GR/IR 科目余额不为零](/01-daily-ops/errors/gr-ir-not-cleared)。
- **行项目显示开关**：科目在 `FS00` 控制数据未勾「行项目显示」时，`FBL3N` 只能看余额出不了清单——先回主数据补开关，新过账起才出明细（以你的系统为准）。
- **S/4 上换入口**：S/4HANA 用 `FAGLL03` 并选分类账（如 0L），漏选分类账金额「少一截」。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| GR/IR 期末挂账不清 | `FBL3N` 未清项明细，`MB5S` 比收货开票差异 | [GR/IR 科目余额不为零](/01-daily-ops/errors/gr-ir-not-cleared) |
| 银行科目未清项堆积 | 是否未清项待对账单导入配对 | [银行对账](/03-config-notes/bank-reconciliation) |
| S/4 上清单为空 | 改用 `FAGLL03` 并核对分类账 | [ECC 与 S/4HANA 差异总表](/00-about/version-matrix) |
| 科目只出余额不出明细 | `FS00`「行项目显示」是否激活 | `FS00` 科目控制数据补开关 |

## 验证

输入科目 191100、公司代码 1000、勾「未清项」运行：能列出 GR/IR 未清行项目，双击进 `FB03`；清单合计与 `FAGLB03`/`FS10N` 的科目未清余额口径可对上（ECC 直接比，S/4 用 `FAGLL03` 复核）。
