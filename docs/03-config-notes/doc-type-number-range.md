## 一句话结论

> 凭证类型（`OBA7`）决定允许的科目类型、供应商/客户借贷属性与挂哪个号码段键；号段按公司代码 + 年度分内部/外部区间（`OBN1`），`FBN1` 看已用状态——号段连续、业务归口正确，过账才可追溯。

## 症状

- 年中过账突然报「号码段已用尽」类错误（消息号以你的系统为准），当天 `FB50`、接口作业、自动过账全部卡死。
- 新年度第一天开账，才发现没给新年度维护号段区间。
- 外部号段与业务单据号混用，`FB03` 按凭证号查出来的业务对不上口径。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 蓝图号段余量不足，业务量增长把段用尽 | `FBN1` 查当年已用比例 | 扩大区间上限并复盘规划 |
| 号段未按年度维护（新年度无区间） | `FBN1` 切到新年度看区间 | 补年度区间再放行过账 |
| 外部号段当内部用（或反之），凭证号与业务单据号混淆 | `OBA7` 查类型挂的号段键与内外部属性 | 分清内外部，规范取号来源 |
| 凭证类型允许的科目类型过宽，业务串段 | `OBA7` 查允许科目类型 | 收紧配置，存量错误冲销纠正 |

## 配错会怎样

- 号段用尽当天月结停摆，`F110` 这类批量作业整批失败，影响面是全公司代码。
- 外部号重复或缺号：审计追溯断链，每个缺号都要逐笔写解释。
- 类型允许错科目类型：本应走统驭科目的业务进了总账段，报表口径和自动清账全乱。

## 怎么配置

1. `OBA7` 每个凭证类型看三件事：允许的科目类型（S 总账、K 供应商、D 客户、A 资产、M 物料）、供应商/客户的借贷属性（普通/贷项）、挂的号码段键。
2. 记牢骨干五件（标准示例）：`SA` 总账凭证（`FB50` 默认）、`KR` 供应商发票（`FB60` 默认）、`KZ` 供应商付款（`F-53` 默认）、`RE` 客户发票、`DZ` 客户收款（`F-28` 默认）。
3. 号段规划：`OBN1` 按公司代码 + 年度给号段键分内部/外部区间；蓝图按年度凭证量留余量（如 KR 年 10 万张，区间给到 50 万），并设 80% 用量预警线。
4. 外部号段只给明确需要的业务（如接口带入上游单号），录入的外部号必须唯一。
5. 审计口径：连续性 = 缺号有解释——跳号成因（号缓冲、年度切换等）登记在案；`FB03` 按号抽查凭证类型与业务一致（用法见 [T-Code 速查](/01-daily-ops/tcode-cards)）。

```mermaid
flowchart LR
    A[凭证类型] --> B[号码段键]
    B --> C[公司代码加年度]
    C --> D[内部或外部区间]
    D --> E[凭证号]
    E --> F[FB03 可追溯]
```

## 怎么验证

公司代码 1000，看 2026 年度的号段。

**验证 T-Code**：`FBN1`
**验证判据**：各在用号段当年已用比例 < 80%；`FB03` 按号段区间抽查：KR 段内均为供应商发票（对应 200001 这类业务）、DZ 段内均为客户收款、SA 段内均为总账凭证。
**失败对照**：某段已用 ≥ 80% → 立即扩区间并复盘蓝图余量；段内混入其他业务 → 回 `OBA7` 查该类型的允许科目类型与号段挂载是否被改动。
