# AFAB 折旧过账报错或事后余额不平

> 一句话：先问「期间内改没改资产」——改过先 `AFAR` 重建折旧，再 `AFAB` 测试运行，顺序反了白忙。

## 消息文本

现象：`AFAB` 运行报错（会话中断、科目缺失等，消息随场景而异），或跑完后 `AW01N` 折旧额与总账对不上。消息号以你的系统为准。

## 什么时候出现

- 期间内改了折旧参数、使用年限或资本化日期。
- 后台运行被中断，`AFAB` 状态卡住。
- 想给已关前期补折旧被拒。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. 期间内资产主数据/折旧参数变更后未重建（最常见） | `AFAR` 对受影响资产重建 | 重建后 `AFAB` 选「重复」重跑，补过差额 |
| 2. 计划运行未完成就中断，状态不一致 | `AFAB` 首屏看状态与作业日志 | 按提示「重启」或完成被中断的会话 |
| 3. 前期已关，补前期折旧被拒 | 输入前期期间看报错 | 前期差异走计划外折旧/资产浏览器调整，别硬开期间 |
| 4. S/4 新资产会计技术清账科目缺失 | 看错误日志技术科目提示（如 `OADB`） | 补配技术清账科目后重跑 |

## 怎么验证

**验证 T-Code**：`AFAB`
**验证判据**：测试运行错误清单为空；正式运行后抽查 `AW01N` 已过账折旧等于总账累计折旧当期发生额
**失败对照**：测试仍报错 → 按清单逐条处理，多集中在第 1、4 类
