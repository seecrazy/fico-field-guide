# F.13 — 自动清账（逐字段详解）

## 界面与入口

`F.13` 按清账准则批量自动清未清项，是月结清理 GR/IR、银行、税务科目的主力。与手工清账分工——`F.13` 清「准则能配对」的量，配不上的回落 `F-44`/`F-32` 手工；GR/IR 排查见 [GR/IR 科目余额不为零](/01-daily-ops/errors/gr-ir-not-cleared)。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 公司代码 | 决定在哪个公司跑自动清账 | 填错公司白跑一轮，目标科目一动不动 |
| 总账科目（区间） | 限定要清的科目，如 GR/IR 191100 | 区间没覆盖目标科目，统计全 0 还以为「已清干净」 |
| 凭证日期/过账日期范围 | 收窄参与清账的凭证 | 范围漏了旧凭证，未清项原样挂着 |
| 清账准则勾选（凭证号、参考、采购订单号、分配等） | 决定两项须一致到什么程度才配对 | 没勾对一项都清不掉；勾太多则本可配对的也配不上 |
| 附加选择（凭证类型等） | 进一步限定参与项 | 限太窄漏项，限太宽跑得慢 |
| 测试运行 | 只出清单不动账 | 不勾直接正式跑，误清后要 `FBRA` 逐笔重置 |
| 明细清单 | 输出可清/不可清明细 | 不勾只看统计，漏清原因无从查起 |
| 清账过账日期 | 决定清账凭证落哪个期间 | 落已关期间正式运行报「过账期间未开」 |

### 关键字段深讲

- **清账准则**：准则 = 参与匹配的字段集合，两边未清项在这些字段完全一致（金额等额、方向相反）才配对；可用准则由后台配置（经典路径常提 `OB74`，以你的系统为准）。错误模式：以为「同科目就能清」——不配采购订单号，GR 与 IR 各挂各的；或勾了不该一致的分配号，能清的也卡住。先跑测试运行看「已选/已清/不可清」统计再调准则。
- **测试运行惯例**：正式前必跑测试，核对可清清单与金额；正式后再跑一次测试，可清项应为空（只剩真实差异）。
- **自动/手工临界**：金额不等（超容差）、跨凭证货币、缺准则字段的项，`F.13` 一律不动——不是故障，是留给人工的业务差异。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| GR/IR 跑完仍挂账 | 测试运行看不可清原因；`MB5S` 比收货开票 | [GR/IR 科目余额不为零](/01-daily-ops/errors/gr-ir-not-cleared) |
| 银行科目清不掉 | 是否对账单未导入、金额不配 | [银行对账](/03-config-notes/bank-reconciliation) |
| 正式运行报期间错 | 清账过账日期所在期间 | [过账期间未开](/01-daily-ops/errors/posting-period-not-open) |
| 误清/清错组合 | `FBRA` 重置对应清账凭证 | [FB08 凭证冲销失败](/01-daily-ops/errors/reversal-not-possible) |

## 验证

公司代码 1000、科目区间含 191100、勾「测试运行」：核对可清清单与 GR/IR 未清明细一致，不可清项的原因能对应到业务差异，再正式运行。
