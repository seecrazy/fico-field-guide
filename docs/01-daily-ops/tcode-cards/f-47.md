# F-47 — 预付款请求登记（逐字段详解）

## 界面与入口

`F-47` 登记供应商预付款请求（down payment request），是「请求→审批→付款」链路的起点。`F-47` 只做统计性登记、不生成真实会计凭证；`F-48`（或带出请求的 `F110`）才真正过账付款。两者都走标识 F，背景见 [特别总账标识](/03-config-notes/ap-special-gl)。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 供应商 | 决定请求挂到哪个供应商账户 | 输错供应商，审批和付款都找错对象 |
| 公司代码 | 决定请求的记账公司 | 填错公司付款运行取不到该请求 |
| 凭证日期 | 请求的凭证头部日期 | 只影响凭证显示，不影响付款 |
| 过账日期 | 决定统计凭证落在哪个期间 | 落在已关期间保存即报「过账期间未开」 |
| 币种/金额 | 请求的付款金额 | 金额录错原样流进付款运行，多付/少付 |
| 特别总账标识 | 预付请求必须选 F | 不带 F 登记成普通统计项，后续 `F-48`/`F110` 无法按预付处理 |
| 基准日期/付款条件 | 决定请求的净付款日（到期日） | 基准日错则到期日整体偏移，付款运行提前/滞后取单 |
| 凭证抬头文本 | 请求摘要，审批人看的说明 | 空着难追溯，审批人不知道这笔请求是什么 |

### 关键字段深讲

- **特别总账标识 F**：标识决定请求挂哪个备选统驭科目、能否被付款运行识别为预付请求。错误模式：以为随便登一个请求就行，漏选 F 后 `F110` 不带出、`F-48` 也对不上，只能冲销重登。取值含义以你的系统配置为准。
- **统计性不动账**：`F-47` 只写统计凭证（noted item），不改应付余额、不进总账。误解一：登记完以为钱已付出；误解二：`FB03` 查不到凭证以为失败——去 `FBL1N` 勾「统计项目」才能看到。
- **到期日与审批流**：基准日期+付款条件算出净付款日，`F110` 按到期日筛选请求；请求常配单独付款方式/单独付款标识以便审批后单独放行，惯例见 [F110 自动付款](/03-config-notes/ap-auto-payment)。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| 以为钱已付出 | `FBL1N` 勾「统计项目」只见请求；真付款要 `F-48` | [特别总账标识](/03-config-notes/ap-special-gl) |
| `F110` 不带出预付请求 | 请求的付款方式、到期日、公司代码 | [F110 付款运行无提案](/01-daily-ops/errors/f110-no-proposal) |
| 保存报期间错 | 统计凭证的过账日期所在期间 | [过账期间未开](/01-daily-ops/errors/posting-period-not-open) |
| 请求到期日不对 | 基准日期与付款条件 | [付款到期日不对](/01-daily-ops/errors/due-date-wrong) |

## 验证

对供应商 200001、公司代码 1000、标识 F 登记一笔小额请求并保存：`FB03` 查不到真实凭证属正常；`FBL1N` 勾「未清项+统计项目」能看到该请求，净付款日与付款条件计算一致。
