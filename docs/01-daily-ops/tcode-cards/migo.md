# MIGO — 收发货过账（逐字段详解）

## 界面与入口

`MIGO` 是 MM 货物移动的统一框架入口，用「动作 + 参照」组合覆盖收货、发货、转储、冲销。与 `MIRO` 是一对：`MIGO` 动库存并挂 GR/IR，`MIRO` 收发票并清账。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 动作 | 定业务场景：A01 收货、A02 退货等 | 选成退货/冲销，方向反转全错 |
| 参照 | 定从哪种单据带行：R01 采购订单、R08 订单等 | 参照选错，带不出目标行项目 |
| 单据号 + 行项目 | 定 PO/交货的哪个行收货，带出数量、价格、科目分配 | 行选错＝收错料错价，GR/IR 与 PO 对不上 |
| 移动类型 | 数量与方向的最终决定者：101 收货、102 冲销、261 发料到订单、501 免费收货 | 手工覆盖后科目确定链（GBB 修改码）变化，串科目 |
| 工厂 | 定评估区域与 OBYC 评估分组码 | 工厂错，命中另一套科目规则或报无法确定科目 |
| 库存地点 | 库存管理最细层级，不影响金额 | 报「库存地点不存在」，需先 `MMSC` 扩展 |
| 数量 + 单位 | 定凭证金额（数量 × PO 价）与库存增减 | 超收被容差拦下；单位换算错数量放大几十倍 |
| 科目分配类别 K | 成本中心/订单收货：不进库存，直接借费用 | 该走 K 的做了库存收货，费用与存货同时失真 |
| 评估类（自动带出） | 取自物料主数据会计 1 视图，定 OBYC 命中行 | 评估类空或错，保存报「无法确定科目」 |
| 抬头：过账日期 | 定 FI 落账期间 | 落在 MM/FI 已关期间，保存即报期间错 |

### 关键字段深讲

**移动类型**：决定数量方向与借贷科目。101 是 PO 收货默认值，102 是镜像冲销，261 发料去生产订单，501 无 PO 免费收货（只进库存不挂 GR/IR）。排查科目问题第一步：先看移动类型对应的科目修改码，再查 `OBYC`。取值：参照带出默认、可覆盖——覆盖即风险。

**评估类 → OBYC 命中链**：物料主数据（`MM03` 会计 1 视图）评估类 × 事务（BSX/WRX/GBB 等）× 评估分组码（`OMWD`→`OMSY`）三层筛出科目；任何一层断了，收货就「有物料凭证、无 FI 凭证」。

**科目分配 K**：PO 行科目分配类别为 K 时，收货不借存货、直接借费用科目，成本中心取自 PO 行。PO 建时漏了科目分配，收货后只能整行冲销重建。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| 收货成功但 `FB03` 无凭证 | OBYC 的 BSX/WRX × 评估类 | [MIGO 收货但 FI 无凭证](/01-daily-ops/errors/migo-no-fi-doc) |
| 保存报无法确定科目 | `MM03` 评估类与 OBYC 前置链 | [OBYC 配置笔记](/03-config-notes/mm-fi-obyc) |
| 过账日期被拒/期间错 | `MMPV` 当前期与 `OB52` 是否同步 | [MMPV 无法关期](/01-daily-ops/errors/mmpv-cannot-close) |
| 收货后 GR/IR 长挂不清 | `MB5S` 对比收货与开票 | [GR/IR 清账失败](/01-daily-ops/errors/gr-ir-not-cleared) |

## 验证（30-120 秒可执行）

对 1000 一张已批准 PO（RM001）做 MIGO 收货：A01 + R01 + PO 号，数量 1，过账。状态栏应**同时给出物料凭证号与会计凭证号**；`FB03` 查到借存货、贷 GR/IR 分录（科目号以你的系统为准）。只有物料凭证号 → 按 OBYC 命中链排查。
