# 外币过账汇率缺失 — No exchange rate maintained（OB08）

> 一句话：按「货币对 + 汇率类型 + 日期区间」三要素在 `OB08` 里逐项对——缺任何一个都取不到汇率。

## 消息文本

原文现象：`No exchange rate maintained from USD to CNY`（未维护 USD 到 CNY 的汇率）。消息号随触发处不同（FI、FI-AA、MM 各自的消息类），以你的系统为准。

## 什么时候出现

- 录外币凭证时当天没维护当日汇率。
- 收付款用了非常用汇率类型（B 卖出、G 买入）。
- 新启用币种（如首次做 CNY）。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. `OB08` 没有该货币对+日期区间的汇率（最常见） | `OB08` 输入从币/到币+起始日查询 | 补一行覆盖过账日期的汇率 |
| 2. 汇率类型缺失：M 有、B/G 没有 | `OB08` 切换汇率类型（M/B/G）分别查 | 按业务口径补齐所需类型 |
| 3. 报价方向错：须用反向报价维护，或涉及 EUR 的币对没以 EUR 为源货币 | `OBBS` 查反向报价 | 用 `OBBS` 维护反向汇率或调转币对方向 |
| 4. 凭证日期落在汇率有效期之外 | 对比凭证日期与 `OB08` 生效起始日 | 延长汇率区间或改凭证日期 |

## 怎么验证

**验证 T-Code**：`OB08`
**验证判据**：按货币对+汇率类型+凭证日期三要素查询，能看到覆盖该日期的汇率
**失败对照**：查得到仍报缺汇率 → 核对 `FB50` 抬头实际带的汇率类型与货币方向是否与你查的一致

M 是每日平均价，B 卖出、G 买入用于收付款；业务用哪类应在蓝图定死，别临场猜。
