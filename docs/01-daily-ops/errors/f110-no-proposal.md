# F110 付款运行无提案 — 供应商全被排除

> 一句话：提案为空，先去提案编辑看「排除原因」——排除码会直接告诉你根因。

## 消息文本

现象：`F110` 建完提案清单 0 条。提案编辑/日志常见「供应商因排除码被排除」，消息号以你的系统为准。

## 什么时候出现

- 新上线或换付款方式后第一次跑 `F110`。
- 「下个付款日」窗口没覆盖到期日。
- 批量导入的主数据字段不全。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. 主数据支付交易视图未勾该付款方式/无银行数据 | 提案编辑看排除原因，回主数据核对 | 补勾付款方式、补银行数据后重跑 |
| 2. 到期日不在窗口（付款条件+基准日 vs「下个付款日」参数） | `FBL1N` 查到期未清项的净到期日，对比参数 | 调大窗口或修正付款条件 |
| 3. `FBZP` 付款方式+币种未配 | 按公司代码 1000 核对付款方式与币种 | 补齐该组合配置 |
| 4. 付款冻结或金额低于最小付款额 | 提案编辑看排除码指向 | 解冻（走审批）或累计超过最小额再付 |

## 怎么验证

**验证 T-Code**：`FBL1N`
**验证判据**：到期未清项（口径同提案参数）全部进入新提案，无冻结/最小额排除码
**失败对照**：提案仍为空 → 回提案编辑逐户看排除原因，多为第 1、2 类根因
