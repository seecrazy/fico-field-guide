# 付款到期日不对 — 付款条件与基准日计算

> 一句话：到期日 = 基准日 + 条件天数——凭证层条件、基准日类型、条件数值逐个对，别只盯天数。

## 消息文本

现象：`FBL1N` 未清项到期日与预期不符（提前/推后/没反映收货日），付款范围跟着错。非报错消息，以数据为准。

## 什么时候出现

- `FB60` 录发票时改了默认带出的付款条件。
- 同一条件在不同凭证算出不同到期日（基准日类型不同）。
- 分期付款的发票没按期拆分。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. 主数据付款条件与凭证不一致（凭证层可改） | `FB60` 回显凭证条件，对比主数据 | 凭证层改回，主数据同步更正 |
| 2. 基准日类型不同（凭证日期/过账日期/收货日起算） | `OBB8` 查该条件的基准日类型 | 按业务口径改，走配置变更 |
| 3. 分期付款条件被忽略（`OBB9`） | 查分期定义与到期日拆分 | 换正确的分期条件重算 |
| 4. 天数/折扣期敲错（含主数据错） | `OBB8` 核对天数与折扣期数值 | 更正数值，评估存量凭证影响 |

## 怎么验证

**验证 T-Code**：`FBL1N`
**验证判据**：抽查 3 笔，手算（基准日+天数）与到期日列一致；分期各期均正确
**失败对照**：手算对不上 → 先核对凭证的基准日类型，多为第 2 类根因
