# MMPV — 关闭 MM 期间（逐字段详解）

## 界面与入口

`MMPV` 推进公司代码的 MM 期间：关当前期、开下一期，是月结 MM 侧第一步。期间上限配置在 `OMSY`；`OB52` 管 FI 期间，两者各自独立、必须人工对齐。S/4 里它还要排在物料账结算（`CKMLCP`）之前。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 公司代码 | 定给哪个公司推进期间（支持多选批量） | 漏了某公司 → 该公司 `MIGO`/`MIRO` 当场报期间错 |
| 期间号（允许到期间） | 目标允收期，只能 = 当前期 + 1 | 想跳月关到 N+2 被拒——只能一期一期顺序推进 |
| 允许负库存（上一期间） | 决定刚关掉的那期是否容忍负库存 | 物料有负库存却没勾 → 关期后移动被拦，回头补勾 |
| 测试运行 | 只检查不落库，输出将关/将开的期间 | 不先测试直接正式，方向搞反要走开回期间流程补救 |
| 对照：OMSY 当前期 | 进 MMPV 前确认当前期间与目标月相邻 | 不确认现状就填，把「已在 11 月」当「还在 10 月」，目标期填错 |
| 对照：OB52 FI 期间 | FI 与 MM 期间互不联动 | 只关 MM 不看 FI（或反之），收货期与发票期错位 |
| 对照：CKMLCP（S/4） | 物料账结算须先于关期完成 | 结算未完强行关期 → 补结代价远高于按顺序跑 |
| 对照：MB51 在途移动 | 关期前确认无未完成物料凭证 | 有在途事务时 MMPV 报错关不动 |

### 关键字段深讲

**期间号（只能顺序 +1）**：MM 期间没有跳期机制——当前 10 月只能开到 11 月，想一次关两个月必须跑两遍。这是第一高频坑：报错常只说「无法关闭」，先回 `OMSY`/首屏确认当前期间，再判断是否在跳月。

**测试运行**：先勾测试看输出——将关哪期、开哪期、有无阻断项，确认无误再正式执行。正式跑错方向只能开回期间或逐笔处理，代价大，测试标志就是保险栓。

**与 OB52 的独立性**：`MMPV` 只动 MM 期间记录，`OB52` 只动 FI 期间。不同步的典型症状：`MIGO` 被拦（MM 期关）而手工 FI 凭证能过（FI 期开），或反过来。月结日历把两个动作排在一起并留痕。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| 报无法关闭期间 | 是否想跳月 + `MB51` 在途事务 | [MMPV 无法关期](/01-daily-ops/errors/mmpv-cannot-close) |
| MIGO/MIRO 报期间错 | `OMSY` 当前期与 `OB52` 是否同步 | [MMPV 无法关期](/01-daily-ops/errors/mmpv-cannot-close) |
| S/4 关期前物料账未结算 | `CKMLCP` 各步骤状态 | [物料分类账结算](/03-config-notes/ml-closing-s4) |
| 负库存物料关期后被拦 | `MB51` 查负库存移动，补勾允许负库存 | [MMPV 无法关期](/01-daily-ops/errors/mmpv-cannot-close) |

## 验证（30-120 秒可执行）

对 1000 跑测试运行：输出应显示将关 N 期、开 N+1 期且无阻断提示。正式执行后重进 `OMSY`，当前期间已 +1；对已关旧期间试一笔 `MIGO` 收货应被拒。
