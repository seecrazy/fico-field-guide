## 一句话结论

> 一张发票的金额是定价过程逐行算出来的：价格 − 折扣 + 运费 + 税 = 价税合计，每个成分是一个条件类型（示意：PR00 价格、K004 折扣、MWST 税）；条件记录（`VK11` 建、`VK12` 查改）按「客户+物料 > 物料 > 客户组」优先级命中，`VF01` 开票时逐条件拆行传 FI——发票金额与合同对不上，九成是条件记录缺失或优先级被覆盖。

## 症状

- 开票金额与合同不一致：约定卖 1,000，发票开出 950 或 1,073.50，商务与财务各说各话。
- 折扣没带出：K004 的 5% 条件记录明明维护了，订单/发票里折扣行却是空的，客户投诉多收款。
- 税基错：MWST 基数取了 1,000（未扣折扣）而非 950，销项税虚高（税码排查见[税码无效](/01-daily-ops/errors/tax-code-invalid)，档位见[中国本地化](/03-config-notes/cn-localization)）。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 条件记录缺失（客户+物料没维护价格） | `VK12` 按条件类型+完整键查 | `VK11` 补记录，订单重定价 |
| 记录被更高优先级覆盖或有效期不覆盖开票日 | `VK12` 查同条件多层级记录与有效期 | 调整层级取舍或延长有效期 |
| 定价过程确定错（客户定价过程/物料定价组错配） | 查客户、物料销售视图的定价组字段 | 修主数据，对后续单据生效 |
| 条件类型的科目确定缺失 | `FB03` 看拆行，回科目确定反查 | 补科目行（见[SD 收入科目确定](/03-config-notes/sd-revenue-account)） |
| 人工改价未留痕覆盖系统价 | 订单/发票条件屏查人工条件标记 | 改价走审批与留痕口径 |

## 配错会怎样

- 价格错：应收与收入同时错，回款对不上、对账函发不出，月结收入截止性被拖累。
- 折扣错：要么客户多付引发红冲，要么企业少收直接侵蚀毛利，返利与佣金的计算基数跟着错。
- 税基错：销项税多缴或少缴，与申报表勾稽断裂（月末核对见[月结检查清单](/01-daily-ops/month-end-checklist)）。

## 怎么配置

1. **条件类型**（配置入口 V/06，非事务码，以系统为准）：定义每个成分的行为——PR00 基础价格、K004 物料折扣、MWST 销项税为经典示意码；控制项含定价类别、正负号、可否人工修改。
2. **存取顺序**：找条件记录的搜索路径——按「客户+物料 → 客户 → 物料 → 全局」逐级找，命中第一条即停（序列以你的系统为准）。
3. **条件记录**：`VK11` 创建、`VK12` 查改：价格 1,000 挂客户 100001+物料组合，维护金额、币种、条件单位、有效期。
4. **定价过程**：条件行按「步+计数」排列组合，定义从-到小计、需求（如仅开票才带税）、计算公式——一张发票怎么算就是这份序列表。
5. **定价过程确定**：销售区域 + 客户定价过程（客户主数据）+ 物料定价组（物料主数据）+ 单据定价过程 → 唯一确定用哪套定价过程（确定键以系统为准）。
6. **开票传 FI**：`VF01` 按条件类型拆行过账，收入/折扣/税各走各的科目（映射见[SD 收入科目确定](/03-config-notes/sd-revenue-account)，全链见[O2C 流程](/01-daily-ops/flow-o2c)）。

## 参数与组合全解

### 定价过程行结构（每个字段管什么）

| 字段 | 管什么 | 示意 |
|---|---|---|
| 步/计数 | 条件行排列顺序与同层子行 | 步 100 价格、110 折扣、900 税 |
| 条件类型 | 本行算什么 | PR00 / K004 / MWST |
| 从-到小计 | 本行基数取哪段（步号区间或小计字段） | 税行取扣折后净额 950 作税基 |
| 需求 | 什么条件下本行才参与 | 税行只在开票时出现 |
| 计算公式 | 金额怎么算 | 按净价百分比、按毛重 |
| 人工/必需/统计 | 可否手改、缺记录是否报错、只统计不过账 | 统计行只显示不进金额 |

### 条件记录层级优先级（示意，由存取顺序定义）

| 优先级 | 键组合 | 命中场景 |
|---|---|---|
| 1 | 客户+物料 | 协议客户特价，最具体 |
| 2 | 客户+物料组/价格组 | 大类协议价 |
| 3 | 物料 | 公开牌价 |
| 4 | 客户组/价格组 | 渠道价 |
| 5 | 全局兜底 | 无任何协议时的底价 |

层级层数与顺序以你的系统为准；高层有记录时低层不再参与——「牌价顶着特价走」的典型根因。

### 常见条件类型速查（示意码）

| 类别 | 条件类型 | 用法 |
|---|---|---|
| 价格 | PR00 | 基础价，客户+物料记录 |
| 折扣 | K004 / K007 | 物料折扣 / 客户折扣 |
| 运费 | KF00 | 运费，按单位或固定额 |
| 税 | MWST | 销项税，按税码档位计算 |

## 边缘与高级场景

- **追溯定价**：补开历史发票时，条件记录按「单据日期」还是「当前日期」取数由定价日期类型控制，口径错会把 11 月票算进 12 月调价后的价（来源以系统为准）。
- **条件排斥**：同一组互斥条件（多个促销折扣叠乘超政策上限）用排斥组只取最优一个，组内排序与排斥标识决定取舍。
- **人工改价**：条件类型放开人工修改后用户可手改金额——审批与留痕要跟上：用小计把人工改价前后差额显性化，供审批与审计取数（审批实现以项目为准）。
- **红冲复用原价**：贷项凭证参照原单定价日期，保证红冲金额与原票一致，别按新价重算（红冲链见[中国本地化](/03-config-notes/cn-localization)）。

## 实操走查（跟着做一遍）

公司代码/销售组织 1000、客户 100001，10–15 分钟，走通「查价 → 开票 → 拆行 → 对账」闭环。PR00/K004/MWST 为示意码，以你的系统为准。

1. `VK12`：条件类型输 PR00 回车 → 键选择屏输销售组织 1000、客户 100001、任一测试物料 → 回车——预期价格 1,000.00、有效期覆盖今天、条件单位 1 PC。抄下有效期。
2. `VK12`：同法查 K004——预期客户+物料有 5% 折扣记录；若没有，`VK11` 补一条（比率输 5、维护有效期、保存）。
3. 取一张已交货待开票的销售订单（上述客户+物料、数量 1）：`VF01` 输开票参考号回车——预期生成 1 张开票凭证，价税合计 1,073.50。
4. 双击行项目进入明细 →「条件」页签——预期定价行逐行展开：PR00 1,000.00 → K004 −50.00 → 净值 950.00 → MWST 13% 123.50 → 总计 1,073.50。
5. 核对税基：MWST 行的条件基数应显示 950.00（扣折后净额）；若显示 1,000.00，回定价过程查税行「从-到」小计设置。
6. 点「保存」过账——状态栏提示已过账，抄下开票凭证号，经凭证流跳到 FI 凭证号。
7. `FB03`：输 FI 凭证号——净额路线（示意）预期：借应收 100001 1,073.50、贷收入 950.00、贷销项税 123.50；独立折扣科目路线则贷收入 1,000.00、借折扣备抵 50.00（口径见[SD 收入科目确定](/03-config-notes/sd-revenue-account)）。逐行与第 4 步对数，FI 拆行 = 定价逐行结果即闭环。

## 怎么验证

**验证 T-Code**：`VF01`
**验证判据**：一张含 PR00 1,000 + K004 5% + MWST 13% 的发票过账后，`FB03` 会计凭证拆行与定价屏逐行一致——净额 950.00 进收入（或收入 1,000.00 + 折扣备抵 50.00）、销项税 123.50 = 950 × 13%、应收 1,073.50；税基取扣折后净额 950。
**失败对照**：折扣没带出 → `VK12` 查 K004 记录与有效期，再查存取顺序是否被高层记录挡住；金额走了牌价 → 查客户/物料定价组是否错配到兜底层；税基错 → 回定价过程查税行从-到小计；FI 缺行 → 查条件类型的科目确定；报错另见[税码无效](/01-daily-ops/errors/tax-code-invalid)，版本差异见[版本矩阵](/00-about/version-matrix)。
