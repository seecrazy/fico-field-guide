# 凭证号跳号或缺号 — 号码段缓冲与审计核对

> 一句话：跳号多数是号码段缓冲（取号未用），不是丢数据——审计要的是缺号清单加解释，不是补号。

## 消息文本

现象：`FB03` 里凭证号不连续（10000047 后直接 10000050），审计追问缺号去向。非报错消息，以缺号清单为准。

## 什么时候出现

- RFC/并行过账后抽查凭证号。
- 过账失败回滚：号已取走但凭证没存进去。
- 跨环境传输后号码段状态与预期不一致。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. 号码段缓冲：取号未用即跳（RFC/并行主因） | `FBN1` 看号码段当前状态与缓冲设定 | 无需修复，登记清单归档说明 |
| 2. 过账失败回滚：号已取、凭证未生成 | `FB03` 按缺号逐个查，确认无凭证 | 登记回滚原因备查 |
| 3. 外部号码段手工录入跳号 | `OBA7` 看凭证类型号码段内部/外部 | 规范手工编号或改内部号码段 |
| 4. 传输/拷贝环境号码段差异 | 对比源/目标环境区间与状态 | 按传输规范对齐并记录 |

## 怎么验证

**验证 T-Code**：`FBN1`
**验证判据**：号码段当前状态与 `FB03` 查到的最后凭证号一致（缓冲可解释的缺口除外）
**失败对照**：状态号远超最后凭证号 → 核对后台作业与接口日志，多为第 1 类根因

## 相关注释

不要重排或补录缺号——技术不可行、合规不接受。定期 `FBN1` 核对状态，缺号做清单加原因归档。
