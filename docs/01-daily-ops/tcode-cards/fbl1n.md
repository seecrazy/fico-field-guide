# FBL1N — 供应商行项目清单（逐字段详解）

## 界面与入口

`FBL1N` 与 `FK10N` 分工：`FK10N` 只看供应商各期间余额，`FBL1N` 下列行项目明细、双击可钻取 `FB03` 看凭证，是应付对账与清账前的第一入口。总账版 `FBL3N`、客户版 `FBL5N` 同构操作。

## 字段逐个讲

| 字段 | 作用 | 填错会怎样 |
|---|---|---|
| 供应商 | 限定查询对象，支持区间/多选 | 留空全量跑清单巨大甚至超时；输错号「无数据」被误读成漏记账 |
| 公司代码 | 决定读哪个公司的行项目 | 填错公司查到空清单；供应商无该公司段时同样为空 |
| 未清项 | 只列未清发票/付款，账龄与 `F110` 提案取此口径 | 误勾「全部」算账龄，已清旧账混入账龄区间 |
| 已清项 | 列已清账项，可再限清账日期 | 清账日期范围太窄，早期已清项看不到 |
| 普通项目 | 显示常规发票、付款、贷项 | 不勾清单为空或只剩特别总账项，误判科目余额异常 |
| 特别总账事务 | 显示预付（F）、汇票（A）等挂备选统驭科目的项 | 漏勾以为 `F-48` 预付「没入账」，其实只是没显示 |
| 统计项目 | 显示 `F-47` 预付请求等统计性登记 | 漏勾以为 `F-47` 白做了；统计项不进余额，别当漏账追 |
| 日期范围（过账/凭证/到期日） | 收窄行项目区间 | 范围太窄漏旧账，合计与试算表对不上 |
| 币种 | 决定金额显示口径 | 本币/凭证币混淆时合计差一笔折算额 |

### 关键字段深讲

- **特别总账事务**：预付、汇票不走普通应付统驭科目，挂备选统驭科目，默认不显示。标识取值来自 `FBKP` 配置（F=预付、A=汇票，以你的系统为准）。错误模式：`F-48` 过完账看不到，以为失败又付一次——双重付款风险。见 [特别总账标识](/03-config-notes/ap-special-gl)。
- **统计项目**：`F-47` 生成的是统计凭证，不动总账，只在此勾选下可见。错误模式：查无此笔就重登，重复请求进付款运行。
- **未清/已清三选**：余额=未清+已清；与 `FK10N` 对不上先核勾选口径与日期，再怀疑记账。

## 高频错误与排查路径

| 症状 | 先查什么 | 去哪页 |
|---|---|---|
| 预付款/汇票在清单看不到 | 勾「特别总账事务」重跑 | [特别总账标识](/03-config-notes/ap-special-gl) |
| 发票到期日与合同不符 | 行项目的付款条件与基准日 | [付款到期日不对](/01-daily-ops/errors/due-date-wrong) |
| `F110` 不给某供应商付款 | `FBL1N` 未清项口径、付款方式与冻结标识 | [F110 付款运行无提案](/01-daily-ops/errors/f110-no-proposal) |
| 行项目合计与余额不平 | 三个项目类型勾选是否全开 | `FK10N` 按期间核对余额 |

## 验证

输入供应商 200001、公司代码 1000、勾「未清项」并全选三个项目类型运行：双击任一行能进 `FB03`；未清+已清合计与 `FK10N` 余额一致。
