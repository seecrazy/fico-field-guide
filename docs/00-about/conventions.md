# 写作约定与占位符

本页是全站的写作宪法。**CI 会机器执行其中可机判的部分**（见 `scripts/check-structure.mjs`），不可机判的部分靠模板约束。想贡献内容前，先读完本页。

## 三条硬规则（CI 阻断级）

### 规则 1：配置笔记必须含「验证三元组」

每篇 `03-config-notes/` 与报错速查页面，正文必须包含以下三个标记：

```markdown
**验证 T-Code**：`FB03`
**验证判据**：执行后 XX 科目余额应为 0
**失败对照**：若余额 ≠ 0，检查 YY 是否已执行
```

价值主张：写错了但验证方法对，读者 30 秒发现；写对了但没给验证方法，CI 拒绝合并。

### 规则 2：每页必须有验证日期和环境

Frontmatter 强制字段：

```yaml
verifiedOn: 2026-11-11
verifiedEnv: "IDES S/4HANA 2023, CC 1000"
```

- `verifiedOn` 必须是真实日历日期（`2026-02-30` 会被 CI 拒绝）。
- 构建时按日期注入降级：>12 个月黄色警告，>24 个月红色警示。机器按日期管，不需要人工盘点。

### 规则 3：报错页强制根因排序表

不写「可能的原因」，写按概率排序的根因清单：

```markdown
| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. FS00 中科目未扩展到该公司代码 | FS00 查公司代码层 | 创建公司代码层 |
```

表头必须含「| 根因」两字（CI 按此识别）。读者按顺序试，试到哪条对上就是哪条。

## Frontmatter 字段规范

| 字段 | 必填范围 | 类型 | 说明 |
|---|---|---|---|
| `title` | 配置笔记 / 报错页 | 字符串 | 页面标题，含主题与副题 |
| `verifiedOn` | 配置笔记 / 报错页 | `YYYY-MM-DD` | 最后一次复核日期 |
| `verifiedEnv` | 配置笔记 / 报错页 | 字符串 | 验证环境（见下「环境写法」） |
| `version` | 配置笔记 | `[ECC]` / `[S/4HANA]` / `[ECC, S/4HANA]` | 适用版本 |
| `module` | 配置笔记 | 字符串 | 如 `FI-GL`、`FI-AA`、`MM-FI`、`CO-OM` |
| `difficulty` | 配置笔记 | 入门 / 中 / 高 | 配置难度 |
| `severity` | 报错页 | 高频 / 中频 / 低频 | 出现频率 |
| `tcodes` | 全部内容页（推荐） | `[FB50, FB03]` | 本页涉及的 T-Code，喂给总索引生成器 |
| `feedback` | 可选 | `false` | 关闭底部反馈按钮（仅首页/导航页用） |

注意：frontmatter 解析器是零依赖的轻量实现（`scripts/lib/frontmatter.mjs`），只支持标量与行内数组，**不要写嵌套结构**。

## 环境写法

`verifiedEnv` 推荐写法（占位符环境也如实写，不冒充真实系统）：

```yaml
# 真实系统验证过
verifiedEnv: "客户测试机 S/4HANA 2023 FPS01, CC 1000"

# 依 SAP 标准行为撰写（本仓库初始内容的口径）
verifiedEnv: "SAP 标准行为（ECC 6.0 / S/4HANA 2023），示例公司代码 1000"
```

## 占位符与脱敏约定

- **公司代码一律 `1000`**，工厂 `1000`，成本中心 `1000` 起——不出现真实客户编号。
- 客户/供应商主数据用 `客户 100001`、`供应商 200001` 等明显示例号。
- 任何真实项目名、用户名、内网地址、IP 不得出现；gitleaks 在 CI 中扫描密钥类泄漏。
- 截图：宽度 ≤ 1200px，压缩后放 `docs/public/images/`，敏感字段打码。

## 术语与格式

- T-Code 一律用行内代码：\`FB50\`；消息号写法：\`F5 100\`（消息类 + 空格 + 号）。
- 消息号在不同版本可能不同：正文以**消息文本**为主要索引，消息号放标题辅助检索，并在条目内注明「消息号以你的系统为准」。
- 金额用 `1,000.00 USD` 格式；日期用 `YYYY-MM-DD`。
- 中文为主，SAP 标准术语保留英文原文（如「未清项（open item）」首次出现时）。
- 每页开头有「一句话结论」引用块，让读者 10 秒决定去留。

## Mermaid 图表规范

- 图全部用 Mermaid 声明式绘制（随代码版本控制、GitHub 与 VitePress 原生渲染、diff 可审）。
- 流程图节点 ≤ 12 个，节点文字 ≤ 8 字，方向 `TD`（上下）或 `LR`（左右）按阅读动线选。
- 图是正文的补充，必须能在正文脱离图的情况下理解；图不承载唯一信息。

## 降级与淘汰

- `verifiedOn` 超 12 个月自动黄色警告、超 24 个月红色警示（构建时注入，无需人工标记）。
- 每月维护决策（15 分钟）：GoatCounter 搜索无结果的高频词 → 新增选题；访问最低的页面 → 候选合并或下架。
- 下架不删除历史：移入归档分支或在 frontmatter 加 `archived: true` 并从侧边栏摘除。
