## 一句话结论

> 权限三层：`PFCG` 建角色（单角色/复合角色）→ 角色里挂权限对象（对象带字段值域，如公司代码 1000）→ `SU01` 把角色分给用户；FICO 按「公司代码 + 模块」切角色，月结关键事务单独管控。用户卡权限时第一动作永远是 `SU53`。

## 症状

- 新顾问「能进系统干不了活」：进得了事务码，一执行就弹「无权限」（消息号以你的系统为准）。
- 跨公司代码误记账：本该只许在 1000 记账的用户，把凭证记进了 2000。
- 离职人员账号残留，半年后审计拉在线用户清单才暴露。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 角色值域漏公司代码/成本中心组（如 `F_BKPF_BUK` 值域不含需要的范围） | `SU53` 看被拒对象的字段与值 | `PFCG` 补值域后重新生成角色 |
| 角色改了但缺「生成」步骤，配置未生效 | `PFCG` 看角色是否处于「部分生成/未更改」 | 完成生成并传输，再分给用户 |
| 用户缓冲未刷新（改完权限没重新登录） | 让用户注销重登再试一次 | 重新登录即生效，不用改任何配置 |
| 事务给了但对象没给（`S_TCODE` 有、业务对象缺） | `SUIM` 对比角色的事务清单与对象清单 | 按最小权限补对象与值域 |

## 配错会怎样

- 值域给宽：跨公司代码误记账，合并报表口径被污染，冲销逐笔处理。
- 月结关键事务（`OB52`/`MMPV`/`AFAB`）人人能跑：一次误开/误关期间就是全公司事故。
- 账号残留与权限过宽是审计整改项；职责分离（SoD）要求同一人不能既建供应商又付款，角色设计时要物理隔离。

## 怎么配置

1. 三层结构：`PFCG` 单角色（一个角色只做一件事）→ 复合角色（按岗位拼装多个单角色）→ `SU01` 分配给用户，同时设账号有效期与用户组。
2. FICO 高频权限对象：公司代码级 `F_BKPF_BUK`（凭证头公司代码）、事务码级 `S_TCODE` 是写稳的两个；科目级（科目表层/科目类型）与成本中心级（`K_CCA` 系列活动）的对象名称随版本/组件有差异，以你的系统为准。
3. 角色切法：按「公司代码 + 模块」建只读/记账两档，如 FI-AP-1000 只读（`FB03`/`FBL1N`）、FI-AP-1000 记账（`FB60`/`F-53`）；要管多个公司代码就用复合角色拼，值域显式列出。
4. 月结关键事务 `OB52`、`MMPV`、`AFAB` 单独建角色，只给月结责任人，开关期间动作留痕。
5. SoD 是审计硬要求：建供应商（`XK01`）与执行付款（`F110`/`F-53`）不许进同一个角色。

## 怎么验证

用一个测试用户做双向验证：正向该干活的能干，反向越权的要被拒。公司代码 1000 环境。

**验证 T-Code**：`FB50`
**验证判据**：测试用户对公司代码 1000 过账一张 `FB50` 凭证成功，`SU53` 无失败记录；换未授权的公司代码 2000（示意）过账应被拒，且 `SU53` 显示被拒对象（如 `F_BKPF_BUK` 值域不含 2000）。
**失败对照**：1000 也被拒 → `SUIM` 查该用户的角色是否缺值域或角色未生成；2000 能过 → 值域给宽了，回 `PFCG` 收紧并复盘 SoD 冲突。
