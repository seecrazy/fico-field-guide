# 无权限执行事务 — Authorization check failed（SU53）

> 一句话：别猜角色——让用户报错后立刻跑 `SU53`，最近一次失败的权限检查连对象带值域一屏列全，这是排错唯一正解。

## 消息文本

原文：`You are not authorized to ...`（你无权执行……）；或事务静默退出、公司代码 1000 字段灰掉。消息号以你的系统为准。

## 什么时候出现

- 执行 `FB50`、`F110` 等事务直接报无权限。
- 事务进得去，但公司代码/科目组等字段灰掉或保存被拦。
- 新角色上线后用户第一次进系统。

## 根因（按概率）

| 根因（按概率） | 验证动作 | 修复动作 |
|---|---|---|
| 1. 角色未含该权限对象或值域不在范围 | `SU53` 看失败对象与值 | `PFCG` 补值域→生成→分配 |
| 2. 角色生成了但没分配给用户 | `PFCG` 看用户分配标签 | 分配后重新生成 |
| 3. 用户没重新登录（权限缓冲未刷新） | 注销重进再试 | 重新登录 |
| 4. 事务码级 `S_TCODE` 缺失 | `SU53` 看是否卡在 S_TCODE | 角色补挂该事务码 |
| 5. 配置里权限对象被换（增强或升级改动） | `SUIM` 对比权限变化 | 按新对象补授权（以你的系统为准） |

## 怎么验证

**验证 T-Code**：`SU53`
**验证判据**：修复并重登后重跑事务通过，`SU53` 无新失败记录
**失败对照**：仍报错 → 再跑 `SU53`，常是第二个对象接着拦，逐个补齐

## 相关注释

`SUIM` 反查「谁有什么权限」，`SU01` 看用户主数据。教会用户「报错后第一动作 `SU53`」能省一半来回猜角色。
